# 智能电商客服 Agent

一个将固定 Workflow、可控 Agent 与混合检索结合的中文客服项目。面向商品咨询、订单物流、售后与投诉等场景，在浏览器中呈现流式回答、工具轨迹、可点击来源及独立的处理选项。

## 核心能力

- **知识问答**：商品咨询与退款退货先检索，再检查证据；答案引用能定位到知识原文和章节路径。
- **多步业务查询**：Agent 根据中间结果调用订单、商品、物流工具，并设置决策、工具调用和 token 预算上限。
- **明确的行为边界**：投诉使用固定处理路径；转人工与建工单分开，创建工单需要用户确认。
- **证据不足兜底**：知识无法支持结论时明确拒答，记录低置信度问题。
- **会话持久化**：业务审计和图检查点分别保存，仅将完整完成的历史轮次送回模型。
- **售后结构化提取**：从自然语言中提取订单号、诉求类型和期望方案。

## 技术设计

| 层次 | 技术与职责 |
| --- | --- |
| 对话入口 | 原生 HTML/CSS/JavaScript，FastAPI SSE |
| 确定性编排 | LangGraph State、固定意图分流、证据闸、checkpointer |
| Agent | LangChain 工具调用与有停止条件的 ReAct 循环 |
| 检索 | bge-m3 + Milvus 原生 BM25，中文分词，RRF 融合 |
| 重排 | bge-reranker-v2-m3，Top-10 证据 |
| 数据 | MySQL 保存业务记录与知识原文，PostgreSQL 保存检查点 |
| 模型接入 | OpenAI 兼容协议，模型地址、名称和密钥通过运行配置管理 |

知识检索对 dense 与 BM25 分别取 Top-50；按品类预过滤，并进行检索侧问法归一与同义词扩展。0.7 / 0.8 分档与独立证据核验共同决定回答路径，检索分数不是答案正确率。

## 工程验证

2026-09-22 本地合并后完整自动化验证为 **807 项通过**，覆盖隔离 MySQL、PostgreSQL、Milvus、本地模型及工作流。该结果验证代码与协议，不等同于真实模型准确率。

检索评估比较纯向量、BM25、混合、混合加重排四种策略；分别检查 Recall@K、MRR 与 Faithfulness。正式模型评估仍有失败与误判，因此不以个别演示样例宣称全量质量通过。

## 当前范围

订单、商品与物流使用随机演示数据；转人工为前端模拟。尚未接入真实电商、真人系统、生产鉴权或多租户隔离。指代消解暂为透传，满意度反馈仅保存在浏览器。

本展示包不包含后端源码、完整 Prompt、密钥、数据库导出或开发日志。完整实现保留私有；此包只用于展示项目成果。
